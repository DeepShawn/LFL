<a id="overview"></a>
## 游戏介绍

成年校友**林舟**收到一张没有署名的旧物领取通知。重返校园后，手机时间停在 22:17，广播开始清点人数：原本四十人的名册，却出现了第四十一行。

这里最重要的不是相信谁，而是**辨认证据是否真实**。异常能够改变纸面浮墨、模仿声音，却无法改写旧纸压痕与实物刻痕，也不能替你主动认领一个新身份。

游戏的基本循环是：

```text
探索校园与建筑 → 调查纸张并翻背核验 → 操作谜题取得线索
             → 躲避异常追踪 → 恢复 SAN、保存进度 → 前往下一处目标
```

| 内容 | 说明 |
| --- | --- |
| 双视角探索 | 第一人称 3D 提供空间感；2D 俯视方便辨认道路、墙角与绕行方向 |
| 五栋楼主线 | 行政楼、实验楼、教学楼、宿舍、食堂，按线索逐步开放 |
| 物件解谜 | 建筑木牌排序、电路核验、座位辨认、纸片拼合、归名仪式，以及后续回声与总控调查 |
| 生存压力 | 管理 SAN、体力、手电暴露风险与有限温水补给 |
| 分支选择 | 部分互动会触发额外遭遇；终局选择和支线完成情况决定结局 |
| 重试机制 | 被追上或 SAN 耗尽后，可以回到最近检查点，不必因此重开整个游戏 |

本作不是战斗游戏。当前操作中没有攻击、武器、跳跃或蹲伏；逃生依靠观察、距离、遮挡与行动时机。

依据：[剧情与目标][src-story]、[核心规则][src-game]、[交互界面][src-interactions]。

## 快速开始

1. 打开在线入口，先进入**新手教程**，练习移动、翻纸、定神和躲藏。
2. 完成教程后回到主菜单，首次正式游玩建议选择**简单模式**。教程与两种正式模式的存档分别保存。
3. 入校后留意当前目标，沿校园主路寻找第一栋已开放的建筑。靠近物件出现调查提示后，按 `E`。
4. 调查纸张时，不要只看正面；翻到背面才会核验并收录证据。进入新的室内区域后，先确认出口、安全灯和温水的位置，再处理主要机关。

**不想提前看答案时，优先使用谜题面板中的三级提示。** 提示会逐步从观察方向过渡到直接解法，不需要退出游戏查攻略。

运行需要启用 JavaScript，并通过 HTTP/HTTPS 访问。3D 需要 WebGL2；初始化失败时，可在游戏提示中明确选择**仅以 2D 继续**。不要通过双击 HTML 的 `file://` 文件预览方式运行。

依据：[页面入口][src-index]、[启动与输入处理][src-main]、[提示系统][src-interactions]。

## 操作与界面

### 电脑操作

| 操作 | 按键或方式 | 说明 |
| --- | --- | --- |
| 移动 | `W A S D` | 3D 中相对当前朝向移动；2D 中对应地图的上、左、下、右 |
| 冲刺 | 移动时按住 `Shift` | 消耗体力，并可能暴露位置 |
| 观察 | 鼠标拖动画面或点击后锁定鼠标 | 用于 3D 视角；也可用左右方向键转向 |
| 切换视角 | `V` | 在 3D 与 2D 间切换，设备需支持对应渲染模式 |
| 调查、进入、离开、拾取 | `E` | 作用于附近可交互目标，不是隔墙或远距离操作 |
| 手电 | `F` | 开关手电；当前版本没有电池消耗系统 |
| 饮用温水 | `H` | 需要持有温水，且已脱离追踪 |
| 灯下定神 | 停步后按住 `R` | 必须在已接通的安全灯旁，且不处于追踪状态 |
| 手记 | `J` | 查看当前目标、随身物品、已核验纸张和规则 |
| 校园地图 | `M` | 查看建筑开放状态、当前位置与下一目标 |
| 暂停或关闭面板 | `Esc` | 现场打开暂停菜单；已打开的面板可用关闭按钮或 `Esc` 退出 |

座位和碗的网格还支持键盘选择：`Tab` 进入，方向键移动焦点，`Home / End` 到当前行两端，`Enter` 或空格执行检查。纸片拼合支持点击选片后再点槽位，不必拖拽。

### 手机操作

左侧虚拟摇杆控制移动，拖动画面调整 3D 观察方向；屏幕按钮完成调查、视角切换、手电、温水、定神与冲刺。**冲刺和定神需要按住，而不是只点一下。** 窄屏下，座位、碗和纸片槽位区域可横向滚动。

### 界面怎么看

屏幕会显示当前模式、场景、目标、SAN、体力、温水数量、附近互动提示与保存状态。异常追踪期间还有方向文字提示，帮助判断危险位于地图哪一侧。

`J` 手记只收录已经翻背核验的纸张，不会提前公开所有线索。`M` 地图不是传送菜单，也不会标记敌人位置。

**切换视角不会重置位置、SAN、体力、物品、机关或敌人。** 2D 画面同样有视距和墙体遮挡，不是透视模式。

依据：[输入与 HUD][src-main]、[交互控件][src-interactions]、[2D 渲染][src-renderer2d]、[3D 渲染][src-renderer3d]。

```text
实验楼
  │

  │
食堂
```

五栋楼位于校园纵向主路的同一侧。后续建筑由前一阶段的调查进度解锁，不需要在尚未开放的门口反复尝试。

| 地点 | 开放条件 | 本阶段主要任务 |
| --- | --- | --- |
| 行政楼 | 初始开放 | 调查档案并取得原始名册 |
| 实验楼 | 已取得名册 | 处理本楼电路，辨认机械校铃 |
| 教学楼 | 已完成实验楼分路核验 | 寻找真实座位 |
| 宿舍 | 已完成座位核验 | 拼回旧签离联 |
| 食堂 | 已取得旧签离联 | 完成归名，随后可调查回声 |
| 北门 | 可返回调查；离校另需旧凭 | 在终局核验离校身份 |

五栋楼采用相同的基础碰撞布局。以 2D 的上北下南为参照：**出口在下方中间，安全灯和温水在左下区域，纸张在左上区域，主要谜题在右上区域**。中央隔墙及横墙会阻挡直线移动，需要从缺口绕行。

### 基础物品与设施

| 物品或设施 | 来源 | 用途与限制 |
| --- | --- | --- |
| 手电 | 初始自带并开启 | 扩大可视范围，避免关灯时的异常黑暗消耗；开启时更容易被敌人发现 |
| 值夜温水 | 五栋楼各一个补给点；教程另有独立补给 | 安全时恢复 SAN，数量有限，每个点只能拾取一次 |
| 四十人名册原件 | 行政楼档案谜题 | 后续仪式所需的原始凭证，不是封套或拓片 |
| 旧签离联 | 宿舍纸片谜题 | 证明原有离校记录；归名与北门核验需要它 |
| 个人姓名条 | 食堂归名仪式 | 证明离校者的真实身份 |
| 安全灯 | 北门与各室内场景 | 室内灯需要接入照明检修端口；北门灯初始已启用 |
| 纸张与手记 | 各场景的记录 | 翻背核验后可在手记中复查，不占用消耗品数量 |

名册、旧签离联和姓名条属于关键物品。归名仪式结束后，名册与旧签离联会自动收回，**不会被仪式消耗**。剧情中提到的检修钥匙、柜钥匙等用于说明阶段解锁，不是需要玩家另行装备的独立背包栏位。

按当前地图配置，正式流程全部补给点共可提供简单模式 **10 份**、困难模式 **5 份**温水；教程补给不带入正式存档。

## 模式与生存系统

### 三种模式

| 参数 | 新手教程 | 简单模式 | 困难模式 |
| --- | --- | --- | --- |
| 定位 | 独立操作演习 | 完整正式剧情 | 完整正式剧情 |
| 持续危险 SAN 消耗倍率 | 0 | 1 | 1.5 |
| 安全灯恢复速度 | 12 点/秒 | 5 点/秒 | 3 点/秒 |
| 安全灯恢复上限 | 100 | 80 | 60 |
| 单次新线索奖励 | 10 点 | 10 点 | 6 点 |
| 每份温水恢复 | 35 点 | 30 点 | 20 点 |
| 每个温水点提供 | 2 份 | 2 份 | 1 份 |
| 敌人追踪移动速度 | 1.5 | 2.4 | 3.1 |
| 搜索阶段基础时长 | 4 秒 | 5 秒 | 9 秒 |

速度采用代码中的游戏坐标单位/秒，不是现实米/秒。正式难度使用相同谜题和结局条件；困难主要提高生存压力，不需要重新学习另一套答案。

教程的持续消耗倍率为 0，但会为了教学主动调整 SAN，也会在演习遭遇时扣除一定数值；其 SAN 最低保持在 **15**，不会因耗尽而结束演习。

### SAN 是什么

SAN 表示当前精神稳定程度，初始为 **100**，正式模式范围为 **0—100**。

| SAN 区间 | 状态 | 含义 |
| --- | --- | --- |
| 70—100 | 清醒 | 相对稳定 |
| 40 至低于 70 | 不安 | 压迫感与视觉、声音干扰增加 |
| 大于 0 至低于 40 | 失衡 | 视野进一步受限，更需要优先脱险与恢复 |
| 0 | 失守 | 正式模式失败，可重试检查点 |

低 SAN 会影响画面明暗、可见距离和声音表现，但**不是坏结局判定条件**。

普通安全探索没有全程倒计时式的 SAN 扣除。主要消耗来自异常遭遇、警觉/追逐/搜索状态，以及关掉手电后身处异常黑暗区域且没有有效安全灯庇护的情况。危险与黑暗的持续消耗不相加：处于追踪状态时按危险消耗计算。

### 三种恢复方式

**安全灯定神。** 调查灯座，选择照明检修端口；关闭面板后靠近灯，停步并按住 `R`。必须脱离追踪，而且灯与人物之间不能隔墙。可重复恢复，但只能恢复到对应难度的灯下上限。接通灯不会立即补满 SAN，普通路灯、手电和任意亮处也不等于安全灯。

**核验新证据。** 首次翻背核验纸张，以及通过带有线索奖励的谜题，可以恢复 SAN。相同证据或已完成谜题不能重复刷取奖励；这类奖励可以使 SAN 超过灯下恢复上限，但总值不超过 100。

**饮用温水。** 拾取后按 `H`，安全时消耗一份并恢复 SAN。追踪期间不能喝；正式模式满 SAN 时不会浪费温水。温水同样可以恢复到灯下上限以上，最高为 100。

**资源安排建议：先用灯恢复到上限，再视需要利用新线索或温水继续补充。** 正式模式中，简单 SAN 不高于 70、困难 SAN 不高于 80 时饮水，通常可以完整利用一份温水的恢复量；但进入危险前应优先保证安全，不必为了节省补给冒险。

### 体力与冲刺

体力初始为 100。正常移动速度为 3.3，冲刺速度为 5.5；冲刺每秒消耗 21 点体力，不冲刺时每秒恢复 15 点，步行也会恢复。体力过低时不能持续冲刺。

不要把冲刺当作默认移动方式：它既影响体力，也会被附近敌人侦知。更实用的做法是用短冲刺越过危险暴露段，绕到遮挡后再减速。

## 追逐与躲藏

### 逃生的基本方法

点名者受到事件唤起后，会经历警觉、追逐、搜索和巡逻等状态。**看不见敌人，不等于已经脱离追踪。** 对方失去直接侦测后仍会搜索，而正式模式搜索结束后也可能继续巡逻。

1. **先打断视线。** 利用中央隔墙、拐角、室外树木或花坛等实体遮挡，必要时短冲刺拉开距离。不要沿开阔直线一直跑。
2. **再降低暴露。** 在合适时机关掉手电，远离敌人最后发现你的位置；取得足够距离后停止冲刺，避免隔着墙仍被近距离跑动侦知。
3. **最后确认安全。** 等待界面提示追踪结束，且调查、手记等操作恢复可用，再接灯、定神、喝水或通过出口。敌人仍可能巡逻，不要立即迎面靠近。

安全灯不会清除追踪，切视角不会删除敌人，门口也不是无条件脱险点。警觉、追逐或搜索期间不能通过切换场景绕过危险，不能用手记、地图或调查面板拖到敌人消失；**系统暂停始终可用，但暂停时搜索时间也不会推进。**

<summary><strong>展开：侦测与消耗数值</strong></summary>

| 规则 | 当前实现 |
| --- | --- |

| 关手电的视觉侦测范围 | 距离小于 4.2，且双方之间无遮挡 |

| 正式模式接触失败 | 距离小于 0.85，且无遮挡 |
| 危险持续消耗 | 简单 1.7 SAN/秒；困难 2.55 SAN/秒 |

| 正式异常遭遇的即时消耗 | 简单 8 SAN；困难 12 SAN |

<a id="tutorial"></a>
## 新手教程：入夜演习

教程位于独立房间，不覆盖正式模式。按照目标提示完成以下 **9 项**，全部完成后才会出现可用的“完成教程”入口。

| 项目 | 完成方式 |
| --- | --- |
| 1. 移动 | 用 `WASD` 或摇杆实际移动一段距离 |
| 2. 双视角 | 按 `V` 或视角按钮切换；设备只能运行 2D 时，游戏会豁免这一项 |
| 3. 手电 | 开关一次手电 |
| 4. 纸背核验 | 找到左上区域的演习纸，翻到背面 |
| 5. 练习谜题 | 到右上练习台，选择翻纸确认原痕，以旧痕对应的 17 号完成核验 |
| 6. 灯下恢复 | 到入口左侧接通安全灯，关闭面板后停步定神，让 SAN 实际增加 |
| 7. 饮水 | 取走灯旁温水，按 `H` 或温水按钮使用 |
| 8. 躲藏演习 | 调查右下演练点，启动追逐，借中央隔墙摆脱搜索 |
| 9. 检查点重试 | 演习脱险后打开暂停菜单，选择并确认从最近检查点重新开始 |

练习台完成后会将 SAN 降至不高于 55，方便演示恢复。已经满 SAN 时，仅按住定神不会满足“实际恢复”条件；教程饮水则允许在持有温水且满 SAN 时完成操作，不消耗这份补给。

躲藏训练需要先完成练习台、灯下恢复和饮水。被抓到时会结束这次追逐并把人物送回入口，可以再到演练点重试；这不是正式模式的失败结局。

建议在确认躲藏成功、界面记下进度后再练习检查点重试。重试会完整回退快照；若某个演习项目因此尚未完成，继续按当前提示补齐即可。

依据：[教程步骤][src-story]、[完成条件][src-game]、[教程 HUD 与重试][src-main]。

<a id="save-settings"></a>
## 存档与舒适设置

### 自动存档不等于检查点

游戏使用浏览器 `localStorage`，分别保存教程、简单、困难进度，并按站点部署路径隔离。一个模式的记录同时包含最近安全自动存档与检查点快照。

| 功能 | 恢复内容 |
| --- | --- |
| 主菜单“继续” | 最近一次成功写入的安全自动存档 |
| 暂停或失败后的检查点重试 | 最近检查点的完整状态，而不一定是最近自动保存的位置 |
| 结局页“重返检查点” | 返回该模式最近检查点，继续探索或尝试其他选择 |
| 同模式“新游戏” | 确认后覆盖该模式记录，其他模式不受影响 |

安全探索时约每 10 秒尝试自动保存；重要安全操作也会请求保存。进场、接通安全灯和部分关键进度会请求检查点，但**是否真正写入仍取决于当前安全状态**。

追踪、搜索、敌人过近或存在待触发遭遇时，不覆盖安全记录。对会唤起异常的关键操作，系统尽可能保留操作前的快照。因此，失败重试后有时需要重新完成刚刚触发追逐的谜题，这是保护检查点的正常行为。

重试会同时回退位置、SAN、体力、物品、已拾取补给、机关、线索及敌人等状态；不能只恢复 SAN，同时保留检查点之后的新物品。当前可用视角会保留，避免回到设备无法使用的 3D 模式。

**存档只在本机，不是 GitHub 云存档。** 换设备、换浏览器、清除网站数据、关闭无痕会话，或改变访问域名、协议、端口、部署路径，都可能导致原记录不可见。当前没有跨设备同步、存档导入导出或任意多槽手动存档界面。

存储不可用、容量不足、记录损坏或版本不兼容时，游戏会提示错误。页面内临时检查点不能保证刷新后仍在；出现保存错误时不要把刷新当作无损操作。

### 声音与显示

主菜单和暂停菜单均可进入声音与显示设置，支持静音、总音量、减弱暗角/杂音/镜头特效，以及标准或低功耗画质。减弱特效只改变表现，不改变 SAN 消耗、敌人速度、搜索或结局规则。

声音由 Web Audio 生成，关键危险与规则同时提供文字提示，不要求靠听力通关。浏览器尚未允许音频时，可在设置里点击启用声音；静音也能继续游玩。

依据：[存档结构与校验][src-storage]、[保存时机与设置][src-main]、[音频实现][src-audio]。

## 完整通关攻略

> **剧透警告**：以下包含全部正式谜题答案、异常触发点与真结局路线。展开后阅读。

<details>
<summary><strong>展开完整流程：北门 → 五栋楼 → 回声台 → 行政总控 → 北门</strong></summary>

### 出发前：先建立固定探索顺序

进入每栋新楼后，可按“**认出口 → 接左下安全灯 → 收温水 → 看左上纸背 → 做右上谜题**”的顺序推进。正式谜题并不普遍强制先收录纸背才能输入正确答案，但核验有信息与一次性恢复收益，更适合初次通关。

以下方位以 2D 地图为准。使用 3D 时先确认朝向，不要把“地图左侧”理解成无论朝向哪里都向人物左转。

### 第 0 步：北门与校园

出生后调查附近的校园旧示意图，并翻背核验路线。北门是最后的出口，但此时缺少旧签离联和姓名条，无法直接离校。

沿主路向南走，进入第一栋行政楼。北门安全灯初始已接通，可以作为返回时的恢复位置；它不能替代旧凭，也不会抹去返程追踪。

### 第 1 步：行政楼——打开档案柜

调查左上区域的封套/旧册压痕，翻到纸背；到右上档案台排列五块建筑木牌。

**正确顺序：**

```text
行政楼 → 实验楼 → 教学楼 → 宿舍 → 食堂
```

北门只表示起点，**不是第六块木牌**。点选牌面后会放入下一个空槽；放错可以取回、撤销或重排。五槽排满后提交开柜。

取得的是整本四十人名册原件。真实记录属于第 17 号林舟，第 41 行是没有旧压痕的后添内容。名册到手后，实验楼开放。

行政楼另有广播总控，位于室内偏右下区域。首次到访时不必在这里反复试开关：总控要等取回姓名条后才能核准。

### 第 2 步：实验楼——保留铃灯，只断广播

先接通本房间安全灯、收好温水并核验检修记录。到检修柜，按界面顺序设置：

| 线路 | 正确状态 |
| --- | --- |
| 铃 | 接通 |
| 灯 | 接通 |
| 播 | 断开 |

三个开关初始都为接通，只需将广播切为断开，再提交本楼设置。不要听信纸面“全断”的浮墨。

核验成功后，教学楼解锁，机械校铃与门闩恢复动作，**同时安排一次必经异常遭遇**。先脱险，不要在现场停着等敌人靠近。

真铃的证据是可见的**短、短、长**铃槌动作及门闩联动，而不只是声音。脱险后可调查机械校铃重新观察；错过初次动画不等于永久卡关，观察动作也不是需要抢在几秒内完成的限时谜题。

> 实验楼处理的是本楼分路。即使已经断开这里的广播，行政楼的重复点名总路仍然需要另行处理。

### 第 3 步：教学楼——找回真实座位

核验原始座位表后，打开座位谜题。面向黑板，从前向后分五排，每排从左到右编号：

```text
               黑板 / 前方

第 1 排：  1   2   3   4   5   6   7   8
第 2 排：  9  10  11  12  13  14  15  16
第 3 排： 17  18  19  20  21  22  23  24
第 4 排： 25  26  27  28  29  30  31  32
第 5 排： 33  34  35  36  37  38  39  40

               后方
```

选择 **17 号，即第三排第一列**。网格外的第 41 座不是原始座位；误点可以重选，不会因此直接进入坏结局。

正确核验后宿舍开放，**同时触发另一场必经异常遭遇**。出门前仍需先结束追踪。

### 室内追逐路线参考：实验楼与教学楼

两个必经遭遇都发生在右上谜题完成之后。可参考仓库连续路线测试采用的折线路径：先从谜题附近向左靠近中央隔墙的右侧，再沿墙向下，从中部缺口穿到左半区，最后退向左下区域。关掉手电，利用墙体与距离等待搜索结束。

```text
右上谜题附近
    ↓ 先向左靠中央隔墙右侧
    ↓ 沿墙向下走到中段缺口
    ← 穿过缺口，进入左半区
    ↓ 退向左下区域，拉开距离并停止冲刺
    → 搜索结束后，再恢复 SAN 或返回下方出口
```

对应的源码测试参考点为 `(16, 6) → (16, 17) → (8, 17) → (8, 24)`。这是地形说明，不是游戏内可输入的传送指令；实际走位应根据敌人的方向和当前距离调整，不能把任何一点当成永久无敌点。

### 第 4 步：宿舍——拼回旧签离联

先核验门内便条，再调查右上储物柜。把纸片翻到背面，按撕口和连续压痕排列，不相信正面的新墨。

| 槽位 | 纸片 | 核验内容 |
| --- | --- | --- |
| 上片，界面左槽 | `a` | 第 17 号林舟；上方完整纸边、下方单齿撕口 |
| 中片，界面中槽 | `b` | 状态已离；上方单齿、下方双齿 |
| 下片，界面右槽 | `c` | 时间 22:17；上方双齿、下方完整纸边 |

**答案是 `a → b → c`。** 先点击片段，再点击目标槽；三个槽排好后提交。背面的连续痕迹会对应“离 / 校 / 存根”，无需重新签名。

取得旧签离联后食堂开放。

**可选事件：门外的声音。** 右下方有声音互动，可以隔门核验、保持沉默或开门。稳妥路线选择核验或沉默即可；开门会额外触发可重试的追逐，但不直接判坏结局，也不是取得旧联的必做步骤。

### 第 5 步：食堂——归名仪式

核验归名口诀纸背，再到右上归名桌。需同时完成三件事：

1. 将**名册原件**预摆到灯下位置。
2. 将**旧签离联**预摆到门侧位置。
3. 检查网格外的 **41 号碗**，再点击预选倒扣；1—40 号旧碗不动。

最后提交归名核验。**检查碗不等于倒扣碗**；只选中 41 号、却没有执行预选倒扣，是常见漏步。

成功后取得第 17 号林舟姓名条，名册和旧联自动收回。关闭面板会丢弃尚未提交的预摆，因此不要摆到一半就离开。

此时已经具备离校所需的两份旧凭。只求普通结局，可以不处理后续支线，直接返回北门；真结局则继续下一步。

### 第 6 步：食堂回声台——归还其余应答

取回姓名条后，在归名桌附近找到回声台。这里只需校验 **3 份样本**，不是在全地图逐个寻找 39 件收集品。

| 槽位 | 应放入的声条 |
| --- | --- |
| 一号槽 | 声条 1 |
| 八号槽 | 声条 8 |
| 三十二号槽 | 声条 32 |

按界面顺序选择 **`1 → 8 → 32`** 并提交。样本匹配成功后，三十九道旧应答归回名册。

这些是被循环截留的应答回声，**不是三十九名遇害同学**。归还回声只是终止循环的一半条件，不能替代关闭行政总路。

### 第 7 步：离开食堂——处理返程追踪

**取得姓名条后首次从食堂返回校园，会安排返程异常。** 普通与真结局路线都会遇到它；不是只有选择归还回声才会触发。

离开前在食堂补足 SAN，保留体力。返程时可以参考源码测试的室外路线：先向西侧，也就是地图左边拉开，再沿校园西侧向北绕行，避免一直沿主路与敌人正面相遇。

```text
食堂门外 → 校园西侧边缘 → 沿西侧北上 → 行政楼外侧 / 北门方向
```

测试参考点为 `(4, 96) → (4, 22) → (20, 22)`；途中仍须避让实体障碍。脱离追踪后，真结局路线进入行政楼，普通结局路线继续前往北门。尚在警觉、追逐或搜索状态时，不能强行通过建筑入口。

### 第 8 步：返回行政楼——关闭重复点名总路

取得姓名条后，调查行政楼室内偏右下方的广播总控。这是独立于实验楼分路的第二处电路操作。

**正确设置仍为：铃接通、灯接通、播断开。** 提交总路核准，保留机械校铃与照明，仅停止重复广播。

回声归册与关闭总路都完成后，就具备真结局的附加条件。两项并非代码上强制按此先后顺序完成；推荐先食堂回声台、再行政总控，是为了减少重复跑图。

### 第 9 步：北门——核验旧凭，不补新签

回到北门，调查核验点。确认手中有旧签离联和第 17 号姓名条，然后选择**出示旧联与旧名，核验离校**。

已经归还回声且关闭行政总路，会进入真结局；附加条件尚未全部完成，则进入普通结局。

不要把新签名选项当成离校必需流程。主动确认认领第 41 行会优先导向坏结局，即使其他任务都已完成。

### 谜题答案速查

| 谜题 | 答案 |
| --- | --- |
| 教程练习台 | 核验旧痕对应的 17 号 |
| 行政楼木牌 | 行政楼 → 实验楼 → 教学楼 → 宿舍 → 食堂 |
| 实验楼分路 | 铃开、灯开、广播关 |

## 全部结局

<details>
<summary><strong>展开：三个结局的准确条件与多结局游玩建议</strong></summary>

三个结局都需要先取得**旧签离联和姓名条**，并在北门执行终局选择。

| 结局 | 触发条件 | 结果 |
| --- | --- | --- |
| 普通结局：旧名出门 | 北门核验旧凭离校；回声归册、行政总路关闭两项中至少一项未完成 | 林舟离开，但校园循环尚未完全结束 |
| 真结局：最后一遍点名 | 回声已归册，行政总路已关闭，并在北门核验旧凭离校 | 旧应答归位，重复点名终止 |
| 坏结局：第四十一行 | 在北门主动确认认领第 41 行 | 接受伪造身份；这一选择优先于其他完成条件 |

**坏结局需要明确确认。** 先打开新签名选项，再勾选知情认领，最后确认签署，才会生效。只是查看选项、随后取消，不算认领。

以下情况不会自动锁定坏结局：误选第 41 座、拼错纸片、接错开关、听见门外声音、隔门核验、打开宿舍门、曾被抓住，或曾经 SAN 归零后重试。它们分别属于可修改的谜题操作、可选遭遇或普通失败。

从代码角度，终局逻辑可概括为：

```text
先检查：是否已取得旧签离联与姓名条

主动认领新身份？
  是 → 坏结局
  否 → 回声已归册，并且行政总路已关闭？
         是 → 真结局
         否 → 普通结局
```

### 同一模式尝试多个结局

可以先在未完成两项附加条件时取得普通结局，使用结局页的重返检查点，再尝试坏结局；之后重返检查点，补做回声与总控，最后取得真结局。

实际需要重复哪一段路，取决于最近检查点位置。游戏没有任意多槽存档界面；先完成真结局后，最新检查点可能已经包含全部附加进度，不能保证还能从同一检查点取得普通结局。重新开始同模式会覆盖原记录，操作前应确认。

依据：[终局选择与优先级][src-game]、[认领确认界面][src-interactions]、[结局文本][src-story]、[结局组合测试][src-unit-tests]。

## 常见问题

### 为什么不能调查、看手记、喝水或出门？

检查是否仍在警觉、追逐或搜索状态。绕过墙角后敌人没有立刻出现，不代表搜索已经结束。等待危险提示解除，再尝试操作；系统暂停可用于暂时休息，但不会推进搜索。

### 为什么安全灯亮了，SAN 还是不恢复？

需要在有效灯座附近、与灯之间没有墙、已经脱离追踪，并在关闭面板后停步按住定神。还要确认没有达到当前难度的灯下上限；简单为 80、困难为 60，这不是角色最大 SAN。

### 为什么调查同一张纸没有反复加 SAN？

只有首次翻背核验会获得该证据的一次性奖励。看正面不算核验，重复翻背不刷新奖励。已收录内容可在手记里复查。

### 为什么答对谜题后，重试还要再答一次？

有些谜题会触发追逐，系统可能保留的是操作前检查点。重试将整个世界回退到该快照，不是只把人物救活。

### 2D 能直接看见墙后敌人，或在地图上传送吗？

不能。2D 也应用视距和遮挡；校园地图只提供建筑与目标信息，没有敌人雷达或快速传送功能。

### 时间一直显示 22:17，是不是必须限时通关？

22:17 是剧情设定。当前版本没有以现实时间达到某个上限就自动失败的全局倒计时；需要管理的是遭遇中的 SAN、体力和敌人行为。

### 为什么教程迟迟不能完成？

检查目标栏剩下哪一项。常见遗漏是没有实际恢复 SAN、没拾水就尝试饮用、仅躲到墙后却未等搜索结束，或没有确认执行检查点重试。完成全部九项后再点击完成教程。

### 页面空白、404 或 JavaScript 模块加载失败怎么办？

确认使用 HTTP/HTTPS，网页入口位于正确发布目录，并上传了所有 JS、CSS 和 `vendor/three/` 文件。文件名大小写应保持一致；开发者工具 Network 面板可以定位 404 资源。只上传 ZIP 或只上传 HTML 都不足以运行。

### 为什么听不到声音？

先点击进入游戏，检查静音和总音量，再到设置里尝试启用声音。浏览器未放行音频时仍可使用文字提示游玩。

### 3D 不可用、卡顿或画面中断怎么办？

3D 初始化依赖 WebGL2。可尝试游戏内低功耗画质；初始化失败或图形上下文丢失时，按提示选择 2D 继续。这里不保证所有手机或内置浏览器都有相同的图形兼容性。

### 存档突然不见了怎么办？

先核对设备、浏览器、访问地址、端口和部署路径是否与之前一致，并检查是否处于无痕模式或出现存储错误。不要首先清除网站数据，那会删除本地记录。

上述行为依据：[入口与菜单][src-main]、[核心规则][src-game]、[存档校验][src-storage]、[渲染实现][src-renderer2d]。

<a id="development"></a>
## 本地运行与打包

> 本节命令在完整源码目录 **`WDFZ/campus-horror/`** 中执行。纯静态部署包不包含 npm 项目结构，不适用这些命令。

### 环境与启动

需要 Node.js 和 npm。仓库锁定的 Playwright 开发依赖声明 Node.js **18 及以上**；依赖版本以 `package-lock.json` 为准。

```sh
git clone https://github.com/DeepShawn/WDFZ.git
cd WDFZ/campus-horror

npm ci
npm run prepare:site
npm run dev
```

默认访问 **`http://localhost:4173/`**。预览服务以 `site/` 为站点根目录，并支持通过 `PORT` 环境变量修改端口。

`prepare:site` 会从本地 npm 依赖中准备 Three.js 模块及许可证。首次安装依赖需要访问相应软件分发服务；“无需运行时 CDN”不表示安装开发依赖时无需网络。

### npm 命令

| 命令 | 用途 |
| --- | --- |
| `npm ci` | 按锁文件安装依赖 |
| `npm run prepare:site` | 将 Three.js 模块与许可证准备到 `site/vendor/three/` |
| `npm run dev` | 启动本地静态预览服务 |
| `npm run test:unit` | 运行核心规则测试 |
| `npm run test:browser` | 运行 Playwright 浏览器测试 |
| `npm run package` | 准备依赖、校验相对资源引用并生成部署 ZIP |

### 生成部署包

```sh
npm run package
```

输出为源码目录中的 **`campus-horror-pages.zip`**。脚本把 `site/` 内容放到 ZIP 根目录，同时将 `campus-horror/README.md` 加入 ZIP 根目录。

因此，维护项目说明时可用本文替换 `campus-horror/README.md`；仅把另一份 README 放在仓库最外层，不会自动改变打包脚本收录的那一份。

依据：[项目命令][src-package]、[锁定依赖][src-lock]、[预览服务][src-serve]、[打包逻辑][src-packager]。

<a id="deployment"></a>
## GitHub Pages 部署

### 方式一：发布打包后的静态内容

1. 在完整源码目录运行 `npm run package`，解压生成的部署包。
2. 将**解压出来的全部内容**放入计划发布的仓库或发布分支根目录。`index.html` 必须直接位于这个发布目录中，不要再外包一层文件夹。
3. 保留 `.nojekyll`、所有游戏 JS、CSS、`vendor/three/` 模块及许可证。
4. 在仓库 **Settings → Pages → Build and deployment** 选择 **Deploy from a branch**，选择发布分支及 **`/(root)`**，保存配置并使用 Pages 提供的站点地址访问。

不要只上传 ZIP，也不要只上传 `index.html`。已经打包好的静态内容不需要访客安装 Node.js，也不需要部署后端程序。

### 方式二：从完整源码发布

本仓库完整源码的网页入口是：

```text
campus-horror/site/index.html
```

它不在仓库根目录。直接把源码分支的根目录设为 Pages 首页，不会自动把 `campus-horror/site/` 当作站点根目录。

可以选择发布解压后的独立分支，或自行配置 GitHub Actions：在 `campus-horror/` 安装依赖并运行准备脚本，再把 **`campus-horror/site/`** 作为静态站点产物上传。如果工作目录已经是 `campus-horror/`，对应目录就是 `site/`。

GitHub Pages 的从分支发布选项支持根目录或 `/docs`，不能直接在该下拉菜单中选择任意嵌套的 `campus-horror/site/`。具体操作参见 [GitHub Pages 发布源说明][github-pages]。

项目运行资源使用相对路径，支持类似 `/WDFZ/` 的仓库子路径。无需在游戏代码中填写 GitHub 用户名、仓库名、访问令牌或数据库连接。

依据：[打包实现][src-packager]、[入口引用][src-index]、[项目现有部署说明][src-original-readme]、[GitHub 官方文档][github-pages]。

## 项目结构

以下以 **GitHub 仓库根目录** 为起点；`vendor/three/` 下的运行文件由准备或打包脚本写入，部署 ZIP 则由打包命令生成。

```text
    │   ├── .nojekyll
    │   ├── styles.css
    │   ├── main.js
    │   ├── game.js
    │   ├── world.js

    │           ├── three.core.js
    │           └── LICENSE
    └── campus-horror-pages.zip        # npm run package 生成
```

| 模块 | 主要职责 |
| --- | --- |
| `index.html`、`styles.css` | 标题页、HUD、对话框、移动端布局和视觉样式 |
| `main.js` | 启动、输入、主循环、暂停、界面连接、存档时机与渲染切换 |
| `game.js` | 玩家状态、敌人行为、交互处理、关卡标记、谜题和结局判定 |
| `world.js` | 场景布局、建筑开放条件、物件位置、碰撞、遮挡和寻路 |
| `story.js` | 开场、规则、纸张正反面、目标、教程与结局文本 |
| `interactions.js` | 纸张、谜题、回声、北门、手记、地图等可操作界面 |
| `modes.js`、`sanity.js` | 难度参数、SAN 消耗与恢复、默认设置和存档版本 |
| `storage.js` | 本地记录、完整快照、数据验证与异常处理 |
| `renderer-3d.js` | Three.js / WebGL2 第一人称画面 |
| `renderer-2d.js` | Canvas 2D 俯视画面、视距与遮挡绘制 |
| `audio.js` | Web Audio 环境声、翻页声、心跳与机械铃声 |
| `scripts/` | 静态预览、运行依赖准备、资源引用检查和 ZIP 打包 |
| `tests/` | 规则层测试与真实浏览器交互、渲染测试 |

两套渲染器共用同一份游戏状态，而不是两个独立游戏。修改谜题时应同时核对 `game.js` 的答案、`interactions.js` 的操作界面与 `story.js` 的纸背提示，避免文案和实际判定不一致。

依据：[模块入口][src-main]、[界面样式][src-styles]、[打包脚本][src-packager]、各模块源码。

## 测试

在已经执行 `npm ci`、`npm run prepare:site` 的完整源码目录运行：

```sh
npm run test:unit

# 首次运行浏览器测试前，安装配套 Chromium
npx playwright install chromium
npm run test:browser
```

浏览器测试还需要相应系统运行库。安装 Chromium 是开发测试步骤，不是玩家访问网页的前置条件。

规则测试覆盖 SAN 边界、难度差异、一次性奖励、视角状态一致性、碰撞与可达性、关卡答案、结局组合、存档隔离和完整回退，也包含两种正式难度下的连续移动与追逐路线。浏览器测试覆盖实际点击谜题、三个结局界面、触控、存储异常、WebGL 场景与视听反馈。

测试生成的截图位于 `campus-horror/artifacts/`，打包脚本不将该目录作为运行站点内容收录。

在已安装 Xvfb、Mesa 和相应 Chromium 的 Linux 测试环境中，现有项目说明还提供以下软件 OpenGL 配置：

```sh
xvfb-run -a env LIBGL_ALWAYS_SOFTWARE=1 CAMPUS_MESA=1 npm run test:browser
```

**仓库含有测试，不等于当前修改已经通过测试。** 发布前应自行运行并记录结果；浏览器模拟触控也不等于所有安卓、iOS 真机的性能与兼容性验收。

依据：[规则测试][src-unit-tests]、[浏览器测试][src-browser-tests]、[测试环境说明][src-original-readme]。
